# 読書メモの小さなアプリ

課題ID: WEB-005 / 難易度: L4 / 目安: 2〜3回の学習 / 通常の支援上限: H3

## 目的
入力・状態・描画・テストを小さなアプリにまとめる。

## 前提知識
HTML/CSSに加えてPhase 3の変数・関数・配列・DOM・イベント。初回Web基礎ではまだ実施しない。

## 課題
本のタイトルを追加し一覧表示する。空白だけの入力は追加しない。各行を削除でき、件数を表示する。再読み込みで消えるメモリ内保存とし、その制約を画面に示す。

提出先：exercises/web/submissions/WEB-005/attempt-01/。
回答はanswer.md、実行・観察はevidence.md、必要なHTML/CSS/JSはsite/に保存します。
再提出はattempt-02以降へ保存します。本人が作成し、AIの文章を自分の説明として転記しません。

## 制約
ReactやDBはまだ使わない。タイトルをHTMLとして挿入せずテキストとして扱う。

## ヒント
読む前に自分の予想と試行を書き、開いた段階を記録します。
<details>
<summary>H1：必要になったら開く</summary>

入力した値はどこにあり、一覧の正しい状態はどこにあるか。

</details>

<details>
<summary>H2：必要になったら開く</summary>

配列の状態とDOM表示を区別する。

</details>

<details>
<summary>H3：必要になったら開く</summary>

入力を検証→状態を変更→表示を更新の3つに分け、1つずつ確認する。

</details>

## 完了条件
追加、削除、件数、空白入力、同名2件、再読み込みを確認する。文字列<b>例</b>を入力してもタグとして実行されない。

## チェックポイント
1件目と2件目を独立して削除できる。実装方針と1つの不具合調査を説明する。
実行した環境、手順、期待、実際、AI支援の最大レベルをevidence.mdに記録します。
Coachは対象範囲だけ採点し、[評価基準](../../../docs/assessment/rubric.md)を参照します。

## 発展課題
JavaScriptとテストの学習後、検証や状態更新を関数に分けVitestで境界値を検証する。
