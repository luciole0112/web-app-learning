# Web通信を自分の言葉で予測する

課題ID: WEB-001 / 難易度: L1 / 目安: 20分 / 通常の支援上限: H3

## 目的
クライアント、サーバー、URL、ステータスを関連付ける。

## 前提知識
[HTTP教材](../../../curriculum/01_web_basics/02-http.md)

## 課題
図書検索サイトで「本を検索する」場面を図または文章にする。誰が依頼し、何を返すか書く。200、404、サーバー停止時をどう区別するか説明する。

提出先：exercises/web/submissions/WEB-001/attempt-01/。
回答はanswer.md、実行・観察はevidence.md、必要なHTML/CSS/JSはsite/に保存します。
再提出はattempt-02以降へ保存します。本人が作成し、AIの文章を自分の説明として転記しません。

## 制約
説明問題。これだけでPracticeやIndependentを実装可能と判定しない。

## ヒント
読む前に自分の予想と試行を書き、開いた段階を記録します。
<details>
<summary>H1：必要になったら開く</summary>

どこからどこへ依頼が移動するか。

</details>

<details>
<summary>H2：必要になったら開く</summary>

通信自体の失敗と、エラー内容を含む返答を分ける。

</details>

<details>
<summary>H3：必要になったら開く</summary>

リクエストのメソッド・宛先と、レスポンスのステータス・本文を箱で分けて書く。

</details>

## 完了条件
登場する役割、依頼、返答、3つの状態を自分の言葉で説明している。

## チェックポイント
画面に何か出たことだけで通信成功としない。404をサーバー停止と同一視しない。
実行した環境、手順、期待、実際、AI支援の最大レベルをevidence.mdに記録します。
Coachは対象範囲だけ採点し、[評価基準](../../../docs/assessment/rubric.md)を参照します。

## 発展課題
画像だけ表示されない時、どの通信を見るか説明する。
