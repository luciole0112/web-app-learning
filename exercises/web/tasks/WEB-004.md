# 体験会の申込フォームを作る

課題ID: WEB-004 / 難易度: L3 / 目安: 45分 / 通常の支援上限: H3

## 目的
意味のある入力欄、キーボード操作、入力検証を組み合わせる。

## 前提知識
[フォーム教材](../../../curriculum/01_web_basics/03-forms.md)

## 課題
架空の体験会フォームを作る。ニックネーム（必須）、メール（必須・email）、希望コース（select）、送信ボタンを付ける。全項目にlabelを関連付ける。空欄、不正メール、ダミー正常入力を試す。

提出先：exercises/web/submissions/WEB-004/attempt-01/。
回答はanswer.md、実行・観察はevidence.md、必要なHTML/CSS/JSはsite/に保存します。
再提出はattempt-02以降へ保存します。本人が作成し、AIの文章を自分の説明として転記しません。

## 制約
保存APIは作らない。「受付完了」と偽表示しない。GETで動作確認する場合はダミー情報だけ使う。

## ヒント
読む前に自分の予想と試行を書き、開いた段階を記録します。
<details>
<summary>H1：必要になったら開く</summary>

何を入力するか、入力欄の外に説明があるか。

</details>

<details>
<summary>H2：必要になったら開く</summary>

labelのforとid、送信時のnameを比べる。

</details>

<details>
<summary>H3：必要になったら開く</summary>

入力項目を1つずつ追加し、Tab操作と空欄送信を確認する。

</details>

## 完了条件
ラベルから入力へ移動でき、Tabで操作できる。必須と形式の検証結果を記録し、サーバー検証も必要な理由を説明する。

## チェックポイント
ラベルの一意性、ボタンのtype、送信と保存の違いを確認する。
実行した環境、手順、期待、実際、AI支援の最大レベルをevidence.mdに記録します。
Coachは対象範囲だけ採点し、[評価基準](../../../docs/assessment/rubric.md)を参照します。
