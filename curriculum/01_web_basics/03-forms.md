# フォームで入力の意味を伝える

教材ID: LESSON-WEB-003 / 目安40分 / 到達条件: ラベル付き入力を作りブラウザーの検証を説明できる。

## この教材で学ぶこと
label、input、buttonの役割と、入力の不備を伝える方法です。

## 前提知識
[HTMLとCSS](01-html-css.md)、[HTTP](02-http.md)。

## なぜ必要なのか
入力欄があっても何を入れるか分からなければ使えません。
入力しやすい画面と、サーバーでの正しい検証の両方が必要です。

## 基礎概念
labelは入力欄の説明です。forとinputのidを一致させると関連付けられます。
nameはフォーム送信時の項目名です。idと役割が異なります。
requiredは未入力を、type=emailはメール形式をブラウザーが確認する助けになります。
これだけで安全なサーバー処理になるわけではなく、API側にも検証が必要です。

## 具体例
住所を入力する欄に説明がないと、建物名が必要か分かりません。
入力例だけを薄い文字で表示するplaceholderは、常に見えるラベルの代わりにはなりません。

## コード例
これは表示と入力検証の例です。保存する処理はありません。実在の個人情報を入れないでください。
```html
<form method="get">
  <label for="contact">連絡先メール（練習用）</label>
  <input id="contact" name="contact" type="email" required>
  <button type="submit">形式を確かめる</button>
</form>
```
送信できると現在のURLに入力値がクエリーとして付く場合があります。
GETのURLにパスワードなどの秘密を載せてはいけません。
[フォームの公式解説](https://developer.mozilla.org/ja/docs/Learn_web_development/Core/Structuring_content/HTML_forms)を参照できます。

## 実践
1. labelをクリックすると入力欄にフォーカスが移るか確認します。
2. Tabで入力からボタンへ移動できるか確認します。
3. 空欄、不正なメール形式、ダミーの正しい形式を試します。
4. 送信できたこととDBに保存されたことは別だと説明します。
5. 開発者ツールでrequiredを外した場合を予測します。実験後は元に戻します。

## 理解度チェック
- for、id、nameは何のためにありますか。
- ブラウザーの検証だけでは、なぜ不正入力を防ぎきれませんか。
- リクエストが送られたことと、保存されたことをどう区別しますか。

## よくある間違い
ラベルの関連付け忘れ、ボタンのtypeを意識しないこと、placeholderだけで説明することです。
フォームの送信はページ移動を起こす場合があり、JavaScriptで扱う時は挙動を改めて学びます。

## 実務ではどう使うか
Reactでも使いやすいフォームの基礎は同じです。
APIの検証エラーをどの入力欄に戻すかも設計します。
