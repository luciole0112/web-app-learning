# HTTPのリクエストとレスポンスを観察する

教材ID: LESSON-WEB-002 / 目安45分 / 到達条件: 実際の通信からメソッド・URL・ステータスを説明できる。

## この教材で学ぶこと
ブラウザーからの依頼とサーバーからの返答を、開発者ツールで観察します。

## 前提知識
[HTMLとCSS](01-html-css.md)。観察用のHTMLファイルとPython 3が必要です。
Pythonが使えなければCoachと環境を確認し、実技は未実施として延期します。

## なぜ必要なのか
画面が動かない原因は、画面の処理だけでなく通信にもあります。
「依頼を送れたか」「返答は何だったか」を分けて調べる必要があります。

## 基礎概念
クライアントは依頼する側、サーバーは応答する側です。
HTTPは両者がやり取りするための決まりです。
リクエストにはメソッド、宛先、ヘッダー、必要なら本文があります。
レスポンスにはステータス、ヘッダー、必要なら本文があります。
GETは取得、POSTは作成などの処理、PATCHは部分更新、DELETEは削除に使います。
URLのホストは接続先、ポートはその中のサービスの入口、パスは対象を表します。
HTTPSはHTTPの通信を暗号化して保護します。

## 具体例
図書館で「この本を見せてください」と頼み、「見つかりました」と返ってくる場面に似ています。
通信に成功しても、欲しい本がなければ404という返答になり得ます。
ネットワーク自体の失敗と、HTTPのエラー応答を区別します。

## コード例
次は通信の説明用の模式例で、実際の教材サーバーのヘッダーとは異なることがあります。
```http
GET /index.html HTTP/1.1
Host: 127.0.0.1:8000
```
```http
HTTP/1.1 200 OK
Content-Type: text/html

<h1>Example</h1>
```
200は成功、404は対象が見つからないことを示します。本文がHTMLならブラウザーが表示に使います。
[HTTPステータスの公式解説](https://developer.mozilla.org/ja/docs/Web/HTTP/Reference/Status)も参照できます。

## 実践
1. exercises/web/submissions/WEB-003/attempt-01/siteを作り、自分のindex.htmlを置きます。
2. VS Codeのターミナルでそのsiteフォルダーに移動します。WindowsならGet-Location、macOS/Linuxならpwdで現在地を確認します。
3. その場所で以下を実行します。Windowsでpythonが使えずpyが使える場合はpythonをpyに置き換えます。
```text
python -m http.server 8000 --bind 127.0.0.1
```
4. ブラウザーで http://127.0.0.1:8000/index.html を開きます。
5. 開発者ツールのNetworkを開き、キャッシュを無効にできる場合は無効にして再読み込みします。
6. index.htmlのメソッド、URL、ステータス、Content-Type、本文を確認します。
7. /missing-example.htmlを開いて404を観察します。もし同名のファイルがあるなら、存在しない別名にします。
8. evidence.mdに予測と観察結果を記録し、ターミナルでCtrl+Cを押して停止します。

専用siteフォルダーで起動するのは、他の学習記録や秘密ファイルを配信しないためです。
このサーバーは手元でHTMLを観察する用途であり、本番公開やAPI実装には使いません。
ポートが使用中なら8001など別のポートを選び、URLも同じ番号にします。
停止後にキャッシュから表示されることがあるので、Networkで実際の通信を確認します。

## 理解度チェック
- ファイルが存在しない時と、サーバーが停止している時はどう違いますか。
- URLの8000は何を表しますか。
- 画面の表示だけで通信の成功を断定できないのはなぜですか。

## よくある間違い
file://で開いたページをHTTP通信だと思う、faviconの404を本文の失敗だと思う、
キャッシュされた結果を新しい応答と思うことです。対象の通信行を確認します。

## 実務ではどう使うか
ReactとFastAPIの連携では、画面・通信・API・DBを順に切り分けます。
Networkの証拠があると、どこで失敗しているかを相談しやすくなります。

## まとめ
期待した依頼を送り、どの返答を受けたかを確認します。表示と通信を分けて考えます。
