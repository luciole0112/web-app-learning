# セッションと進捗更新

## 開始
Coachはlearner-profile、roadmap、progress、assessments、historyを読む。
未完了の記録があれば整合を確認し、次に今日使える時間と希望を聞く。
SESSION-YYYYMMDD-NNを重複しないよう採番する。初回は[診断](assessment/initial-assessment.md)を使う。
一度に学ぶ目標は1つ。所要時間は見積もりと明示する。

## 専門Agentへの引き継ぎ
以下を会話に出し、学習者が対象Agentに切り替えて送る。
- 対象IDと目標
- 読むファイル
- 学習者の回答・観察事実
- 現在の支援量と許容上限
- 未解決点
- 依頼する出力とCoachに戻す条件

専門Agentは提案・根拠・未確認事項・推奨する次の作業を返す。
長い報告を保存する場合は学習者が該当課題のevidence.mdかプロジェクトのevidenceに保存する。
教材・演習作成担当は自分の担当ディレクトリへ成果物を保存できる。

## 確定更新：Coachのみ
1. 元のprogressと既存評価IDを確認する。
2. assessmentsに新規評価IDを「pending」として追記する。根拠、変更前後、次の課題を含める。
3. progressの対象行だけ更新し、評価IDを付ける。roadmapを必要に応じて更新する。
4. historyにセッションと評価ID、次回作業を追記する。
5. 関連ファイルのID・点数・状態が一致することを確認し、評価記録を「applied」にする。
6. 学習者に変更点と根拠を提示する。コミットする差分は学習者が確認する。

複数ファイルの更新は原子的ではない。中断時はpendingを読み、更新前後を照合して不足分だけ反映する。
同じ評価IDを二重に適用しない。すでに別の評価がある場合は上書きせず相違を説明して訂正評価を作る。
理由のない点数維持・昇格・降格をしない。評価結果の訂正も履歴として残す。
書き込みツールが使えなければ変更案を提示し、「未保存」と伝える。保存完了を偽らない。
