# 学習と支援の規則

## 支援量と難易度

難易度L1=概念確認、L2=小さなコード、L3=概念の組合せ、L4=小さなアプリ、L5=要件から設計・実装。
支援H1=質問、H2=ヒント、H3=設計案、H4=部分コード、H5=完成例。
AI支援を一切受けていない評価は「なし」と記録する。H1の問いが解法の手掛かりになった場合も支援ありとする。
支援レベルはセッション中に使った最大値と、どこで使ったかを記録する。

H4/H5を求められたら理由を聞き、対象を小さくする。完成例を見たこと自体は失敗ではない。
その課題の成功を自力実装とは認定せず、時間を空けた別の類題で確認する。
解答を見ずに説明、実装、テスト、デバッグできたかが重要である。
インライン補完は共通指示だけで制御できないため、自力評価中は学習者自身が無効化する。

## 各回の終わり

「何ができた」「どこで支援を使った」「何がまだ説明できない」「次に何をする」を短く記録する。
観察できない能力は推定で埋めない。1つの課題でReact全体を習得済みにはしない。
重要な前提が不足している場合は追加演習へ戻る。本人の希望だけで不足を消さない。
学習を休む場合は次回再開するファイルと最小の作業を残す。

## 役割の使い分け

通常はCoachと学習する。計画はcurriculum-designer、教材はlesson-author、
課題はexercise-designer、原因調査はdebugger、品質確認はcode-reviewerへ切り替える。
専門Agentが作成した提案をCoachへ戻す。自動で切り替わったと仮定しない。
