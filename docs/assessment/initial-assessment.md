# 初回スキル診断

診断ID: DIAG-001。担当: learning-coach。
目的は合否判定ではなく、知っていることと必要な練習を区別すること。
目安20〜40分。時間が足りなければ数回に分ける。未回答は未評価とする。

## 開始時
「知らない、やったことがない」と答えてよいと伝える。
1. 作ってみたいWebアプリは何か。
2. 週にどのくらい時間を使えるか、今日は何分使えるか。
3. OS、VS Code、GitHub/Copilot利用の可否、これまで書いたコードを聞く。
個人の実名・年齢・パスワードは不要。自己申告と実演を別に記録する。
診断中はAI補完とヒントを使わない。支援を求めたら学習モードに切り替え、その部分を未評価にする。

## 分岐
完全未経験ならAから一問ずつ出し、Bの小さな実技までで終えてよい。
経験者は知っている分野のCを追加する。全問を一度に提示しない。
「できる」と答えた項目も説明と実技で確認する。環境がない場合は実技を延期する。
この問題一覧は正解集ではない。回答前にCoachが期待回答を読み上げない。

## A：説明と予測
- A1：URLを入力してページが表示されるまで、ブラウザーとサーバーは何をすると思うか。
- A2：HTML、CSS、JavaScriptはそれぞれ何を担当するか。分からなければそう答える。
- A3：画面を再読み込みすると消えるデータと、残るデータの違いを説明できるか。
- A4：GitとGitHubを使った経験はあるか。それぞれ何のために使うか。
観察：自分の言葉か、例との対応があるか、知らないことを区別できるか。

## B：小さな実技
- B1：好きな題材で見出しと段落を含むHTMLファイルを自分で作り、ブラウザーで開く。変更して再読み込みする。
- B2：できる人だけ、3件の買い物の金額から合計を求めるJavaScript関数を書き、空の配列でも確認する。
- B3：できる人だけ、B1の変更前後をGitの差分で確認し、何が変わったか説明する。
提出：作ったファイル、実行方法、結果、説明。学習者はexercises/web/submissions/DIAG-001/attempt-01へ保存する。
Coachは回答を代筆しない。環境がない人にセットアップ完了まで診断を強制しない。

## C：経験者への追加確認
| 対象 | 問いと小さな実演 |
| --- | --- |
| JavaScript | mapとfilterの違いを説明し、条件に一致する商品名一覧を作る。非同期の失敗をどう扱うか説明 |
| TypeScript | 任意項目を持つ型を定義し、値がない場合の扱いを実装 |
| React | 入力と件数表示を持つ小さな画面を作り、stateの置き場所を説明 |
| Python / FastAPI | 関数・型ヒント・例外を説明し、入力と応答の型をAPI設計として示す |
| SQL / PostgreSQL | 2つのテーブルと関連を設計し、関連する行を取得するSQLを書く |
| HTTP / REST | 作成・取得・更新・削除のメソッドと応答、無効入力と不存在の違いを説明 |
| 認証・認可 | ログイン済みでも他人のデータを更新できてはいけない理由と検証方法を示す |
| テスト | 既存の小さな関数に正常・境界・異常のケースを設計し、1つ実行 |
| デバッグ | 自分のエラーを期待・実際・仮説・調査結果に分けて説明 |
| Docker | イメージとコンテナー、DB永続化、設定値の扱いを説明。経験があれば既存環境で実演 |

既存コードの提出でもよいが、本人の担当箇所を示し、その場で小さな変更を説明してもらう。
説明のみで実装力を認定しない。動かせない項目は未実演と残す。

## 終了と反映
[評価基準](rubric.md)で確認した軸だけ採点する。
profileに目標・時間・経験、assessmentsに根拠、progressに対象範囲、
roadmapに開始地点、historyに次回作業をCoachが記録する。
最初の課題を1つ決める。未経験者は[学習方法](../../curriculum/00_orientation/01-learning-method.md)へ。
不足分野は[標準ロードマップ](../../progress/roadmap.md)の前提から補う。

## 診断の成功条件
学習者が「今できること」「まだ未評価のこと」「次にする1つの作業」を説明できる。
高得点や全問終了を成功条件にしない。
